# 上游功能同步与 dsh next 适配计划

本计划覆盖已确认的全部上游功能差异，并保留本仓库的模型能力与请求预算区分、账户隔离、配置并发保护和发布身份。按功能分阶段集成，每阶段完成对应验收后再进入依赖它的阶段。

当前状态：实施中。P1 工程基础及 P2 的选择、批量参数、自定义模型、宿主手改值和密钥管理已落地；逐模型默认思考档仍待原生适配器接入，P2 尚未完成。P3—P8 尚未实施。新增默认值沿用本文建议；既有配置和行为的保留要求继续生效。

## 全程保留的保证

1. 凭据通过宿主凭据服务解析和保存，配置、日志、统计、CSV 与 API 回包不含密钥。更新目标不得变成上游的 npm 包。
2. 全部插件 HTTP 路由继承当前宿主认证；写操作保留来源校验。专用代理使用独立的 loopback 与认证边界，不能因独立监听绕过认证。
3. `contextWindow`、输出能力上限和 `requestOutputBudget` 分别管理；能力上限不会自动变成一次请求的预算。调用方显式请求参数优先于默认值。
4. `selectionKind: explicit` 且 `explicitModels: []` 继续表示一个模型也不注册。不能直接套用上游 `visibleModels: []` 表示全选的语义。
5. API 地址、主凭据名、活动账户或活动密钥变化时，上一账户的套餐与缓存失效；失败或过期的异步读取不能重新写回。
6. 配置写入先持久化再承认成功，保留已有写入顺序和旧发现结果失效保护。只改目标字段，保留其他 provider 和不属于本插件的配置。
7. 未知能力、未知用量与失败状态保留为未知或错误。不能用 0%、空列表或固定大上下文伪装有效结果。

## 各阶段设计与验收要点

### P1 工程与契约基础

- 梳理既有 Config、公开接口、服务注入和客户端 slot，建立后续各阶段的配置归属与兼容规则。复用现有 `migrationRevision` 和写入串行化入口，不另建迁移框架。
- 先验证逐模型默认思考档在调用配置冻结前的挂载点，以及历史图片卸载与会话回放的公开接口。next 的 `llm/stream` 收到的是已冻结请求，`ConfigureCall` 由调用方传入，不能据此假定插件已有全局修改入口。若缺少公开接入点，先形成最小的宿主／适配器扩展方案并标明依赖，不修改全局 DSH 安装，也不在代理里隐式改写这些参数来冒充完整支持。
- 客户端请求统一处理取消与超时；边界覆盖响应头和实际响应体读取。已有调用方 signal 与超时共同生效，卸载、重试和失败后恢复交互状态。
- 按目标 next 的实际主题 token 修正旧 token，检查浅色、深色、焦点、悬停及配额警告。
- 构建增加本地静态检查和不写文件的 `--check`；沿用现有客户端打包方式，保留产物大小约束。静态检查发现的实际错误随本阶段修复。
- 验收慢响应、响应体停滞、取消、错误后的再次操作，以及现有 57 项回归中的受影响部分。

### P2 模型和凭据管理

模型管理扩展现有 `modelOverrides`、`customModels` 和选择模式，避免并存两套互相覆盖的模型配置。单模型显式设置优先于批量默认，批量默认优先于已知目录；恢复继承只清除对应覆盖。套餐过滤仅在当前凭据身份对应的套餐已经成功验证时生效，关闭过滤不丢弃原来的手动选择。

- 新增全选、仅套餐模型、清理失效选择等操作，始终保留“显式空选择”的含义。
- 自定义模型表单支持 ID、名称和能力参数；未知能力保持未知，不自动赋予图像或思考支持。
- 支持批量上下文／输出参数及恢复原厂值；恢复输出能力时不同时改写请求预算，除非用户明确选择修改预算。
- 逐模型默认思考档只允许该模型支持的值；显式关闭或调用方选档优先。代理与直连的默认档语义应一致，在原生调用配置冻结前应用，不在序列化后偷偷覆盖。
- 识别宿主模型页的手工修改，将其纳入明确的覆盖归属和优先级；套餐同步不能覆盖有效手改值，用户主动恢复目录值时才能清除它。
- 密钥发现由用户触发，限于已知 Cline CLI、VS Code、Cursor 配置路径及约定环境变量；发现列表仅返回来源、状态和遮罩，导入由服务端取值并调用凭据服务。支持重复发现去重、坏文件、缺失路径和无权限情况。
- 提供独立的保存前验证接口，返回验证结果及可展示的账户／套餐信息；验证本身不保存凭据。导入继续使用已有“账号名先写入，密钥失败后回滚”的保证。
- 验收旧配置重复迁移、空选择、套餐读取失败、账户／地址／密钥切换期间的并发读写、手改值保留，以及验证失败后的再次操作。

### P3 代理、会话路由与图片预算

代理是本阶段的主要新边界。采用专用 `127.0.0.1` 动态端口，避免依赖 Desktop 宿主 Web 路由的额外访问头。provider 只引用代理凭据名；代理地址、密钥和端口随生命周期同步，停用时恢复真实上游 provider 配置。

- 直连保留已有“失败后切换后续请求账户”的行为。代理的请求内重试与会话改路由不借助反复写全局 `activeAccount` 实现，防止并发会话互相改变钉选。
- 路由顺序建议为：明确的逐模型路由 → 手动钉选 → 当前会话绑定 → 所选策略。账户不可用时按已展示的冷却与回退规则寻找替代；没有可用账户时返回真实失败。
- 会话表有容量与空闲过期上限；账户删除、密钥替换和配置变化能使失效绑定退出，不影响已冻结的在途请求。
- 首个有效的文本、思考或工具调用输出交付前，可以因明确可重试故障尝试其他账户；输出交付后不能切换账户并重放请求。保活和空 SSE 帧不算有效输出。
- 候选尝试次数受可用账户数和请求总期限限制，同一次请求不循环重试同一账户。代理管理重试时协调宿主重试策略，避免两层重试相乘；直连保留宿主既有策略。
- 覆盖 429／402、认证失败、5xx、断连、首输出超时、空流、HTTP 200 内的错误、非流式 body 超时，以及全部候选失败。错误类别、状态和可用的 `Retry-After` 不能丢失。
- 客户端取消或断开会取消在途 fetch、释放 reader、定时器和监听器；插件停用释放专用服务器。代理内的 token 记录与宿主 stream hook 明确区分，供 P4 使用。
- 图片尺寸和编码字节限制优先复用 next 的 `maxRequestImageBytes`、`requestImagePixelBudget`、`requestImageMaxBytes`。历史图片卸载与完整 HTTP 请求体上限是不同功能，分别配置；不重复处理同一张图片，不改写持久化会话原图。
- 开启历史图片卸载时通过宿主支持的附件／回放接入点采用稳定占位表示，保留顺序和可追溯引用；不能让宿主仍记录发送原图而代理静默删除它。完整请求体预算计入文本、工具定义、图片和 JSON 开销。文本本身超限时明确报错，不能靠删除全部图片宣称请求已经合规。
- 验收流式／非流式请求、分片 SSE、思考和工具调用、不同会话并发、取消、停用与重启，以及图片保留／卸载／超预算路径。

### P4 持久化统计

建立一个请求计量入口，复用 next 的 `usage` 和 `finish` 事件。统计同时区分逻辑请求、上游尝试、失败与限流，使一次请求的账户重试可以解释且不会重复计为多个成功请求。

- 统计输入、输出、缓存读取／写入和推理 token，以及延迟、首输出延迟、请求结果；保存 provider、模型、会话、账户的非秘密标识。
- next 的输入与缓存计数互斥，推理 token 已包含在输出中；不能再次相加。流中缺失 usage 时保留“未知”，不能把固定估算当实测。
- 正常对话、代理请求、冒烟请求分别标明来源。代理已记录的请求不再由 stream hook 重复累计。
- 持久化按当前 profile 隔离，遵守宿主路径与 `DSH_HOME`，采用原子写入；启动读取成功后才开始合并新计量。损坏文件和写盘错误有明确恢复与错误反馈。
- 提供汇总、按日／模型／账户查询、CSV 导出和统计重置；重置只影响统计，不触碰凭据或模型。CSV 文本字段正确转义并处理公式注入风险。
- 验收重启、配置切换、磁盘失败、损坏文件、并发请求、无 usage、缓存命中、推理计数和代理重试去重。

### P5 使用界面和诊断

- 注册侧栏配额入口，支持展开和收起两种形态；详情使用宿主弹窗，不替换当前对话。样式在 slot 渲染前加载，规则限制在本插件贡献的元素内。
- 五小时／周／月配额保留未知状态；倒计时明确区分未来重置、正在重置及缺失时间。展示用读取仍不改变限流选路依据。
- 输入框组件按当前会话和 ClinePass 请求展示用量。优先使用宿主会话投影，混用多个 provider 时不得把其他 provider 或全局历史累计冒充本会话 ClinePass 用量。
- 费用按可核对的价格来源或用户明确配置的费率估算，标出单位与估算性质；未知费率显示不可计算。订阅配额不等同于逐 token 账单，不复制上游固定美元费率。
- 模型测速使用真实流式请求测量首个有效输出延迟，同时展示总耗时；普通非流式冒烟延迟保持原名称。支持取消与超时，不以“测速成功”承诺模型全部能力。
- 补齐 `/cline stats`、`/cline telemetry`、`/cline account`、`/cline use` 和 `/cline ping [model]`，保留当前命令返回结构、纯文本及遮罩规则。
- 新 UI 状态有中英文文案；核对其他受支持语言的回退。浏览器验收加载、空数据、错误、恢复、当前会话切换、1280px／390px、深浅主题及键盘关闭弹窗。

### P6 原生网页搜索

按 next 的 `WebSearchProvider` 注册到 `ctx.web`。上游当前代码调用 `${baseUrl}/alpha/web-search`，并非 changelog 中写的 DuckDuckGo；该渠道接口及返回形状须在本阶段核实。

- `available()` 只做本地能力判断，不发网络请求；搜索使用当前活动凭据、`maxResults`、明确的超时和调用方取消信号。
- 成功结果返回真实 URL、标题、摘要及契约要求的字段；401、402、429、5xx、网络失败和取消保留可辨识错误。真正零结果才能返回空来源列表。
- 不隐式改用其他搜索提供方或其他网站。接口不可用时说明限制，不能靠返回空结果通过验收。
- 验收原生 `ctx.web` 的选择／注册／卸载、结果数量、取消、错误映射和账户切换。mock 与真实渠道验证分别记录；真实请求沿用用户已有的外部调用授权边界。

### P7 更新流程

更新功能面向本仓库的安装来源，优先复用 next 的 `pluginManager.listBundles()`、`inspect()`、`installBundle()`、`waitForInstall()` 和 `cancelInstall()`。这些接口已经拥有 profile 锁、安装取消与结果报告，不能再无条件叠加第二套自制锁和进程管理。

- 从安装来源识别 GitHub／registry／本地目录／tgz，校验包身份。GitHub 更新固定到检查得到的明确提交；不得将 `dsh-clinepass` 替换为 `@goodandready/dsh-clinebot`。
- 支持版本／提交检查、可用更新展示及用户点击后安装；不增加无人确认的后台安装。继续使用本仓库 GitHub 交付路径，不为实现更新而取消 `private: true` 或发布 npm。
- 本地开发目录或 tgz 没有可推导的远程更新目标时，说明安装来源并提供显式选择目标的路径，不能自动猜另一个包。
- 准确区分检查失败、无更新、安装中、已安装、需重启、应用失败和取消。校验 `ChangeResult.application` 与实际安装结果，进程退出 0 不等于功能已应用。
- 更新页展示变更来源与目标版本；检查失败不得显示“已是最新”。操作可取消，失败后的配置、凭据与统计保持可读取。
- 验收并发更新、离线、取消、超时、包身份不符、兼容性拒绝、安装成功但需重启，以及重启后实际加载的版本。只操作隔离 profile。

### P8 集成与交付准备

- 在每阶段同步相应配置说明、API 语义、默认值和错误行为；最终统一核对三份 README、CHANGELOG 与验证记录。
- 迁移覆盖当前 `0.5.7` 配置、旧模型 ID、显式空选择、手动钉选、已有覆盖和模型缓存；重复启动／迁移保持稳定。新增字段不删除未知的有效宿主配置。
- 通过打包产物安装到独立 `DSH_HOME`，从原生适配器和浏览器走真实调用链。覆盖代理／直连、无密钥／多账户、设置页两个入口、停用／重启和更新后恢复。
- CLI Web 与 Desktop 分别验收。当前旧宿主历史记录只证明已有功能；新增功能的支持范围与能力缺失提示按实际验收结果填写，不自动宣称旧宿主全面支持。
- 最终回归覆盖新功能、认证边界、并发迁移、模型参数序列化和资源释放；测试、截图、mock、真实渠道与真实平台证据分别记录，遇到实际失败再修复和重测。
- 检查 tarball 的客户端可重建性、依赖、大小、文件清单与秘密排除。交付准备不包含推送、tag、Release、npm 发布、交互 profile 升级或全局 DSH 升级。

## 新增功能的默认行为建议

| 项目 | 建议行为 | 原因 |
| --- | --- | --- |
| 已有 provider／模型选择／账户配置 | 升级保留 | 功能同步不能静默改变既有请求和可见模型 |
| 代理模式 | 迁移后保持直连，用户开启代理 | 让新增路由和请求内重试成为明确选择 |
| 套餐自动过滤 | 默认关闭，开启后作用于已验证套餐 | 保留现有选择，避免离线或换账户时意外清空模型 |
| 历史图片卸载 | 默认关闭；图片与请求体预算仍有明确边界 | 卸载会改变模型可见内容，需要可理解的开关 |
| 网页搜索 | 注册能力由开关控制，默认关闭，不替用户改全局提供方 | 保留当前搜索配置和可见的外部调用选择 |
| 密钥发现与导入 | 用户触发发现、选择后导入 | 不在后台扫描本地配置或自动导入秘密 |
| 统计与费用 | 新请求开始计量；缺失 usage／费率显示未知 | 不回填虚构历史或虚构账单 |
| 侧栏配额、输入框组件 | 可单独开关，停用后释放计时器和订阅 | 界面展示可控，后台轮询有生命周期 |
| 更新 | 自动化检查与用户点击安装；安装交给宿主 | 提供一键更新并复用宿主已有保证 |

这些默认值让所有新增能力具备明确入口，同时保持升级前已经可用的请求路径。若实施前用户指定其他默认值，直接修订本表及对应迁移／验收，不扩大成额外的兼容机制。
